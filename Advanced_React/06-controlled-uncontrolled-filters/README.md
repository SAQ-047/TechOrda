# 06. Управляемый и неуправляемый фильтр

[Папка решения на GitHub](https://github.com/SAQ-047/TechOrda/tree/main/Advanced_React/06-controlled-uncontrolled-filters).

Два фильтра одних и тех же четырёх курсов из локального `src/courses.json`. Оба поля начинают со строки `React`; сброс явно очищает запрос до `''` и возвращает все курсы. Зависимости общие с остальными заданиями.

## Кто владеет значением

| Вариант | Текущий ввод | Когда меняется список | Внешний сброс |
| --- | --- | --- | --- |
| Управляемый | `controlledText` в React state; передаётся как `value` | На каждом `onChange` | `setControlledText('')` |
| Неуправляемый | DOM-свойство `input.value`; в JSX только `defaultValue` и `ref` | При «Применить»: чтение `uncontrolledRef.current.value` | Запись `uncontrolledRef.current.value = ''` и `setAppliedQuery('')` |

`ControlledFilter` и `UncontrolledFilter` содержат только подписанный input. Кнопки сброса находятся снаружи этих компонентов, в `App`. В одном input не смешиваются `value` и `defaultValue`; режимы не переключаются во время жизни поля.

`appliedQuery` хранит снимок последнего применённого запроса для отрисовки результатов. Он не передаётся в `value` неуправляемого input, поэтому его наличие не делает поле управляемым. До нажатия кнопки набранный текст и подпись применённого запроса могут различаться — подпись честно относится к списку.

При сбросе неуправляемого варианта недостаточно очистить только `appliedQuery`: текст в DOM остался бы прежним. Недостаточно и только присвоить `.value = ''`: результаты продолжили бы отображать прежний фильтр. Обработчик явно выполняет оба действия. Сброс до пустой строки выбран намеренно; это не встроенный сброс формы к исходной строке `React`.

Обработчики сброса не переводят фокус; при активации с клавиатуры он остаётся на кнопке. После сброса можно вернуться к полю и продолжить ввод. Чтение и запись `ref.current.value` выполняются только в обработчиках, не во время render.

## Почему defaultValue не управляет текущим вводом

`defaultValue` задаёт исходное значение неуправляемого поля. Текущий ввод хранится в DOM и меняется пользователем. После редактирования `input.defaultValue` и `input.value` могут различаться: изменение значения по умолчанию не является контрактом синхронизации текущего текста с React props.

Для постоянного управления нужен `value` со строкой из state и `onChange`, который обновляет её. В неуправляемом варианте действие над текущим значением нужно выполнять явно — например, чтением или записью `.value` в обработчике. Изменение defaultValue может влиять на значение по умолчанию для сброса формы; это отдельное поведение, а не замена `value/onChange`.

## Версии и самопроверка

React / React DOM 19.3.1, Vite 8.3.6, @vitejs/plugin-react 6.3.0. Проверка на Node.js 20.20.2 и npm 10.9.4. Версии и дерево зависимостей закреплены в общих [package.json](../package.json) и [package-lock.json](../package-lock.json).

Проверено 9 ноября 2026 года: `npm ci` и сборка всех шести workspaces прошли. Сценарии в Brave проверены через Playwright Core.

| Проверка | Dev + StrictMode | Production |
| --- | --- | --- |
| Начальное значение обоих полей и запросов | `React`, по одному курсу | То же |

| Неуправляемый ввод | Список меняется только по «Применить» | То же |
| Ввод черновика и render родителя через другой фильтр | Черновик и DOM-узел сохранены | То же |
| Три цикла ввода → применения → сброса | PASS | PASS |
| Повторный сброс и очистка ещё не применённого черновика | Пустые поле и запрос, четыре курса | То же |

| Ошибки JavaScript, загрузки ресурсов и предупреждения React | 0 | 0 |

Проверены запросы `тип`, `сЕРВЕР` и `нет такого курса`: один результат, один и ноль соответственно. После каждого сброса повторный ввод работает. Для неуправляемого фильтра дополнительно проверена очистка черновика, когда применённый запрос уже был пустым: запись в DOM выполняется и без изменения React state. Сброс не перемонтирует input.

В отдельной DOM-проверке после пользовательского ввода `сервер` свойство `input.defaultValue` заменено на другую строку. Текущий `input.value` остался `сервер`, как и положено уже отредактированному неуправляемому полю. Это проверка DOM-свойства, а не дополнительная функция приложения или смена React props.

Ручная проверка:

1. В управляемом поле введите `тип`: список сразу показывает «Типизация данных». Нажмите внешний сброс — поле пустое, показаны четыре курса. Введите новый запрос.
2. В неуправляемом поле введите `сервер`: до «Применить» список остаётся для прежнего запроса. Нажмите «Применить» — показан «Серверный rendering».
3. Наберите новый текст в неуправляемом поле, затем измените управляемый фильтр. Повторный render родителя не должен потерять набранный текст.
4. Сбросьте неуправляемый фильтр: поле и применённый запрос пусты, показаны все курсы. Снова введите запрос и примените его. Повторите цикл.
