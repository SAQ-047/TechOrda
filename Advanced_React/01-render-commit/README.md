# 01. Render и commit на счётчике

Самостоятельный пример для первой работы курса «Продвинутый React». Родитель хранит счётчик и `title`, ребёнок выводит заголовок и постоянный текст. Кнопка перемонтирования меняет `key` ребёнка, вызывая настоящее удаление старого экземпляра и создание нового.

## Запуск

Из корня `Advanced_React`:

```bash
npm ci
npm run dev:01
```

Откройте адрес из терминала (обычно `http://127.0.0.1:5173`) и DevTools → Console. Перед опытом перезагрузите страницу и очистите консоль, чтобы отделить результаты от Fast Refresh после редактирования кода.

Для production:

```bash
npm run build --workspace=01-render-commit
npm run preview:01
```

Вторая команда запускает уже собранное приложение, обычно на `http://127.0.0.1:4173`. Дополнительные проверки StrictMode в этой сборке отключены.

## Что наблюдать

| Действие | Render | Изменения DOM |
| --- | --- | --- |
| Первое открытие | Вызывается `Child`, выводится `[render]` | React создаёт DOM. Наблюдатель подключается позже, в эффекте, поэтому первоначальное создание не попадает в его журнал |
| «Увеличить счётчик» | Вызываются родитель и `Child`; появляется `[render]`, хотя `title` прежний | Число меняется в родителе. В поддереве ребёнка изменений нет, `[DOM]` отсутствует |
| «Изменить title» | `Child` получает новый prop и вычисляет JSX | React меняет текст `h2`; появляется `[DOM]`, обычно с типом `characterData`. Постоянный `p` и сами элементы сохраняются |
| «Перемонтировать ребёнка» | Новый `key` создаёт новый экземпляр `Child` | Старое поддерево заменяется новым. Старый observer отключается; новый подключается после монтажа |

В этом примере нет `memo` или React Compiler: при обновлении родителя обычный дочерний компонент также вычисляется. Одинаковые props не предотвращают такой render автоматически. После вычисления React сравнивает результат с предыдущим и в commit применяет необходимые изменения DOM. Повторный вызов функции сам по себе не означает изменение DOM.

`MutationObserver` сообщает о фактических мутациях асинхронно, после них. Это наблюдение за DOM в выбранном узле, а не счётчик всех commit React. Отсутствие записей не исключает commit или изменение DOM за пределами этого поддерева. Удаление самого узла ребёнка также не наблюдается его observer: для этого понадобилось бы наблюдать родителя.

В callback сохраняются тип записи, прежний текст и текущий текст узла. Подписка следит за `childList` и `characterData` во всём поддереве. Она создаётся в `useEffect` с `[]`, поэтому обновления счётчика и `title` не создают новых подписок. Замыкание хранит DOM-узел, а не устаревающий `title`. Cleanup всегда вызывает `observer.disconnect()`.

## StrictMode и очистка

`StrictMode` включён в корне. В dev-режиме React дополнительно вызывает функцию компонента для проверки чистоты render. Поэтому для одного действия могут появляться повторные `[render]`. Диагностический `console.log` в теле добавлен по условию; он не меняет DOM и не должен использоваться для подсчёта commit.

При первом монтаже dev-режим также проверяет эффект последовательностью `setup → cleanup → setup`. В консоли это выглядит так:

```text
[observer] setup; active = 1
[observer] cleanup; active = 0
[observer] setup; active = 1
```

После смены `key` сначала отключается прежняя подписка (`active = 0`), затем подключается новая. Дополнительная проверка нового эффекта снова заканчивается значением `1`. Два сообщения setup с cleanup между ними не означают две одновременные подписки. В production дополнительных вызовов StrictMode нет; cleanup при настоящем удалении компонента остаётся.

`activeObservers` — диагностическая переменная для единственного ребёнка в этой работе. Она изменяется только в setup/cleanup эффекта и не участвует в render.
