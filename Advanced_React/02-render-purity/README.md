# 02. Чистота render и выбор курса

Самостоятельный React-пример: четыре курса из `src/courses.json`, кнопка «Выбрать» на каждой карточке и проверочное обновление родителя. Задание 01 сохранено отдельно.

## Что исправлено

В исходном кейсе `localStorage.setItem('selected-course', course.id)` находился в теле `CourseCard`. Поэтому отображение карточки уже меняло внешние данные, а повторный render выполнял новую запись. При отображении списка карточки последовательно перезаписывали общий ключ без выбора пользователя.

В решении `CourseCard` только вычисляет JSX из props. Кнопка получает функцию `onClick={() => onSelect(course.id)}`. Она вызывает `handleSelect` родителя, где выполняются запись id в ключ `selected-course` и обновление локального состояния для подтверждения выбора.

Обработчик передаётся в `onClick`, а не вызывается во время построения JSX. Записи нет в теле компонента, инициализаторе состояния, функции обновления состояния или Effect. Подключён корневой `StrictMode`: дополнительные вызовы render в dev-режиме также не меняют хранилище. StrictMode не вызывает обработчик клика дважды.

До нажатия «Выбрать» приложение не пишет, не удаляет и не очищает данные localStorage. Существующий `selected-course` сохраняется при открытии страницы. После клика хранится id именно той карточки, чью кнопку нажали. Каждый клик выполняет одну запись, включая повторный выбор того же курса. «Повторить render» меняет только счётчик в React state.

Подтверждение выбора на странице отражает клики после её открытия. Чтения сохранённого выбора при монтаже нет; перезагрузка сбрасывает это локальное подтверждение, но сохраняет id в localStorage.

## Почему Effect без клика не подходит

Такой перенос устраняет запись из фазы render, но не выполняет требование «сохранять только по нажатию»:

```jsx
useEffect(() => {
  localStorage.setItem('selected-course', course.id);
}, [course.id]);
```

Effect выполнится после начального commit карточки, даже если пользователь ничего не выбирал. При смене `course.id` он выполнится снова; в dev-режиме StrictMode дополнительно проверяет начальный запуск эффекта. Массив `[]` также не решает задачу: запись всё равно произойдёт после монтажа без клика. Здесь причина записи — конкретное действие пользователя, поэтому запись находится непосредственно в его обработчике.

## Ручная самопроверка

1. Откройте DevTools → Application → Local Storage → `http://127.0.0.1:5174`. Для проверки пустого хранилища удалите `selected-course` вручную. Само приложение очистку не выполняет.
2. Перезагрузите страницу. Ключ не должен появиться. Нажмите «Повторить render» несколько раз: ключ по-прежнему отсутствует.
3. Нажмите «Выбрать» у «React-интерфейсы». Значение ключа должно стать `react`.
4. Повторите render: значение остаётся `react`. Выберите «Типизация данных»: значение становится `typescript`, в том числе при `seats: 0`, поскольку запрета выбора по числу мест в этом задании нет.
5. Перезагрузите страницу: `typescript` сохранён. Без нового клика отображение карточек и проверочные render его не перезаписывают.

Для чтения значения в Console:

```js
localStorage.getItem('selected-course');
```

Одного сравнения значений недостаточно, чтобы исключить повторную запись того же id: `setItem` мог бы записать то же значение. Поэтому браузерная проверка отдельно считает вызовы методов изменения Storage до загрузки React.

## Результат проверки

Проверено 9 ноября 2026 года. Установка `npm ci` из корня и `npm run build --workspace=02-render-purity` завершились успешно.

Браузерная проверка выполнялась через Playwright Core и установленный Brave. До загрузки React перехватывались `Storage.prototype.setItem`, `removeItem` и `clear`. Для каждого сценария использовался отдельный браузерный контекст.

| Dev + StrictMode | `previous-course` | 0 | 5 / 5 | 0 |
| Production | Ключ отсутствует | 0 | 5 / 5 | 0 |
| Production | `previous-course` | 0 | 5 / 5 | 0 |

В каждом сценарии проверены выбор всех четырёх курсов, повторный выбор того же курса, восемь проверочных render, перезагрузка страницы и render после неё. Каждый клик сохранил точный id своей карточки. Сохранённый выбор пережил перезагрузку, посторонние ключи не изменились. Ошибок JavaScript и загрузки ресурсов нет; при ширине 360 px горизонтальная прокрутка отсутствует.

Все четыре сценария — **PASS**. Проверочный сценарий выполнялся вне учебного проекта; тестовый runner и тестовые зависимости в приложение не добавлены.
